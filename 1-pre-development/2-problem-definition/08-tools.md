## 08 – Tools for Problem Definition

This file lists **practical tools** that help you run the Problem Definition phase.  
Use what your organization already has; the method matters more than the specific brand.

We group tools by purpose:

- A. Documentation & collaboration
- B. Workshops & mapping
- C. Analytics & data
- D. Process & operations
- E. Tracking and governance

---

### A. Documentation & Collaboration

**Confluence / Notion / SharePoint / Google Docs**

Use for:

- Writing **problem statement documents**.
- Storing:
  - scope definitions,
  - constraints & assumptions registers,
  - meeting notes.

Tips:

- Create a dedicated space, e.g. `Pre‑development / Problem Definition / <Domain>`.
- Use templates from `23-templates.md` so all problem docs have a **consistent structure**.

---

### B. Workshops & Mapping

**Miro / Mural / FigJam / Lucidchart / Whiteboards**

Use for:

- Running:
  - 5 Whys sessions,
  - current vs desired state mapping,
  - hypothesis trees.
- Facilitating **cross‑functional workshops**.

Artifacts:

- Journey maps,
- problem trees,
- scope diagrams.

In banks/enterprises where some tools are restricted:

- You can use:
  - PowerPoint,
  - Visio,
  - physical whiteboards and photos,
to achieve the same outcomes.

---

### C. Analytics & Data

**Product Analytics (Amplitude, Mixpanel, Pendo, etc.)**

Use for:

- Journey funnels,
- step‑level drop‑offs,
- time‑to‑complete metrics.

**BI Tools (Tableau, Power BI, Looker, Qlik, in‑house dashboards)**

Use for:

- Operational KPIs:
  - SLAs,
  - processing times,
  - throughput,
  - error rates.

Tips:

- Agree with analysts on a **small set of key charts** that directly support your problem statements.
- Link those charts in your problem docs so others can self‑serve.

---

### D. Process & Operations Tools

**Process Modeling Tools (Signavio, Visio, BPMN tools)**  

Use for:

- Mapping **current state**:
  - steps,
  - hand‑offs,
  - systems and roles involved.

**Ticketing / Incident Systems (Jira Service Management, ServiceNow, Zendesk, in‑house)**  

Use for:

- Quantifying and categorizing issues related to the problem area.

Role in Problem Definition:

- Provide:
  - visible evidence of pain,
  - understanding of operational impact.

---

### E. Tracking and Governance

**Jira / Azure DevOps / Trello / Asana**

Use for:

- Tracking **problem statements as artifacts**:
  - one epic or ticket per problem,
  - linked to downstream work items (epics, stories).

Benefits:

- Ensures problem statements:
  - are not lost once solutions start,
  - remain visible to delivery teams.

**Portfolio / Product Discovery Tools (Aha!, Productboard, Jira Product Discovery)**

Use for:

- Linking:
  - problems,
  - opportunities,
  - ideas,
  - and roadmap items,
in a single view.

---

### F. Minimal Tool Stack Example (New Team)

If you are starting from scratch, a **minimal but effective** setup could be:

- Docs: Confluence or Notion.
- Workshops: Miro or a simple whiteboard + photos.
- Data: whatever product analytics / BI your org already has.
- Tracking: Jira or Trello, with one ticket per problem statement.

This is enough to run a solid Problem Definition process.
